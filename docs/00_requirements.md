# gpkg Japanese Style Renderer 要求仕様

## 概要

本プロジェクトはオープンソースの家系図作成ソフトウェア Gramps のエクスポートファイル (`.gpkg`) を、**日本の伝統的な家系図の様式**でレンダリングするためのツールである。

ここでいう「日本の家系図スタイル」とは、単に日本語を表示するという意味ではなく、`__example_data/` のサンプル画像が示す以下のような具体的な組版様式を指す。

- 人物名を **縦書き** で組み、世代は上から下へ、兄弟は右から左へ（右が年長）配置する
- 夫婦を横棒で連結し、親子は直交折れ線のみで接続する
- 名前に続柄（長男・二女）、ふりがな、和暦の生没年を小書きで添える
- 標題を毛筆体の縦書きで掲げる

Gramps 標準の横書きツリー表示ではこの様式は得られないため、独自のレイアウトエンジンと描画層を持つ。

### 想定利用者と利用形態

個人が自家の家系図を作成し、印刷して保存・配布することを主目的とする。個人の家系情報という機微なデータを扱うため、ローカル環境で完結して動作する。

## 用語

| 用語 | 定義 |
|---|---|
| 家系姓 | その家系図の主題となる姓。実データ「山田家」のように複数存在しうる |
| 婚入配偶者 | 家系姓を持つ人物と婚姻して家系図に現れる、外部の家の出身者 |
| 夫婦ユニット | Gramps の family に相当する、レイアウト上の最小配置単位 |
| 系統 | 家系図を分割出力する際の単位となる部分グラフ。サンプル画像の「1 系統 / 2 系統」に相当 |
| 続柄 | 兄弟姉妹内の生まれ順（長男・二女など）。Gramps の `<attribute type="続柄">` に格納 |
| 基準人物 | 家系図の主題となる人物。サンプル画像の「★依頼者」に相当 |
| 奥書 | 図の隅に記す作成日・施主の署名欄 |
| オーバーライド | 自動レイアウト結果に対してユーザーが加えた差分。自動レイアウト結果とは別に保持する |

## 1. 入力データ

### gpkg ファイルの読み込み

**UID**: RQ-01-01 \
**STATUS**: Active

Gramps が出力した `.gpkg` (Gramps Package) を読み込めること。`.gpkg` は tar.gz アーカイブであり、内部の `data.gramps` はさらに gzip 圧縮された Gramps XML であるため、二段階の解凍を要する。XML 名前空間は Gramps のバージョンによって変化する (1.7.1 / 1.7.2 等) ため、名前空間に依存せずローカル要素名で解釈すること。

受入基準: サンプルデータ `山田家系図.gpkg` (人物 136 / 家族 46 / イベント 84 / メディア 75 / メモ 31) を、いずれの要素も欠落させずに読み込めること。

### 関係グラフの構築

**UID**: RQ-01-02 \
**STATUS**: Active

人物の `childof` / `parentin` 参照から親子・夫婦の関係グラフを構築できること。**同一人物が複数の family に属しうる**（養子縁組・再婚）ため、木ではなく DAG として扱い、訪問済み判定によって無限再帰を防ぐこと。

### 実子と養子の区別

**UID**: RQ-01-03 \
**STATUS**: Active

`childref` の `frel` / `mrel` 属性から、父・母それぞれとの関係が実子 (`Birth`) か養子 (`Adopted`) 等かを判別できること。属性が省略されている場合の既定値は `Birth` とする。

### 複数配偶者の扱い

**UID**: RQ-01-04 \
**STATUS**: Active

一人の人物が複数の夫婦関係を持つ場合（再婚等）、そのすべてを保持し表示できること。

### 顔写真の取得

**UID**: RQ-01-05 \
**STATUS**: Active

人物に紐づくメディアオブジェクトの実データをアーカイブから取り出せること。`<file src>` の値がアーカイブ内エントリ名と一致する前提で解決する。

### 独自属性の取り込み

**UID**: RQ-01-06 \
**STATUS**: Active

人物の `<attribute>` のうち、表示に用いる以下を取り込めること。

| 属性 `type` | 用途 |
|---|---|
| `続柄` | 続柄ラベルの表示 (RQ-03-05) |
| `姓(カナ)` / `名(カナ)` | ふりがなの表示 (RQ-03-04) |
| `血液型` | 任意表示項目 |
| `元データID` | 元データとの突合。表示はしない |

### 旧姓の取り込み

**UID**: RQ-01-07 \
**STATUS**: Active

`<name type="Also Known As" alt="1">` に格納された旧姓・改姓前の姓を取り込めること。

### メモの取り込み

**UID**: RQ-01-08 \
**STATUS**: Active

人物に紐づく `<note>` を取り込み、注記の小書き (RQ-03-10) に利用できること。

### 欠損データの許容

**UID**: RQ-01-09 \
**STATUS**: Active

以下の欠損があっても処理を中断せず、判明している範囲で表示すること。実データにはこれらがすべて含まれる。

- 生年・没年が存在しない人物
- 姓を持たない人物（婚入配偶者に多い）
- 父または母の一方のみが判明している家族
- 日付の一部が不明 (`1982-04`, `????-04-08` 等)
- `dateval` 以外の日付表現 (`daterange` / `datespan` / `datestr`)

## 2. 組版・レイアウト規約

### 縦書きを既定とする

**UID**: RQ-02-01 \
**STATUS**: Active

人物名・生没年・標題・注記はいずれも縦書きで組むことを既定とする。

### 世代の進行方向

**UID**: RQ-02-02 \
**STATUS**: Active

世代は図の上から下へ進行させること。同一世代の人物は同一の段に揃えること。

### 兄弟の配置順序

**UID**: RQ-02-03 \
**STATUS**: Active

兄弟姉妹は右から左へ、年長者を右に配置すること。生年が不明な人物は末尾（左端）に置く。

### 夫婦の連結表現

**UID**: RQ-02-04 \
**STATUS**: Active

夫婦は両者の間を短い横棒で連結して表すこと。家系姓を持つ人物を右、婚入配偶者を左に配置する。

### 親子接続線の形状

**UID**: RQ-02-05 \
**STATUS**: Active

親子の接続は直交折れ線のみで描き、斜線を用いないこと。夫婦連結線の中点から下降し、水平の兄弟バーを経て各子へ下降する形とする。

### 養子の線種

**UID**: RQ-02-06 \
**STATUS**: Active

実子は実線、養子は破線で接続し、視覚的に区別できること (RQ-01-03)。

### 婚入配偶者の実家の併記

**UID**: RQ-02-07 \
**STATUS**: Active

婚入配偶者の親が判明している場合、その配偶者の上方に小さく併記できること。実データでは親を持たない人物 46 名の多くがこの用途に該当する。

### レイアウト方向の切替

**UID**: RQ-02-08 \
**STATUS**: Active

縦書き（世代は上→下）を既定としつつ、横書き（世代は左→右）へ切り替えられること。

## 3. 人物ノードの表示要素

### 氏名の表示

**UID**: RQ-03-01 \
**STATUS**: Active

人物の主名を「姓 名」の順で表示すること。名前が不明な人物もノードとして表示すること。

### 婚入配偶者の姓の省略

**UID**: RQ-03-02 \
**STATUS**: Active

婚入配偶者は姓を省いて名のみを表示できること。サンプル画像では家の人物を「山田太郎」、その配偶者を「花子」と表記している。省略するか否かは設定で切り替えられること。

### 旧姓の併記

**UID**: RQ-03-03 \
**STATUS**: Active

旧姓 (RQ-01-07) を併記できること。

### ふりがなの表示

**UID**: RQ-03-04 \
**STATUS**: Active

氏名にふりがなをルビとして添えられること。データ供給元は `姓(カナ)` / `名(カナ)` 属性。

### 続柄ラベル

**UID**: RQ-03-05 \
**STATUS**: Active

続柄（長男・二女など）を氏名の脇に小さく添えられること。実データでは 136 名中 66 名が続柄を持つ。

### 生没年の併記

**UID**: RQ-03-06 \
**STATUS**: Active

生年月日・没年月日を氏名の脇に小書きで添えられること。表記は暦設定 (RQ-04) に従う。

### 顔写真の表示

**UID**: RQ-03-07 \
**STATUS**: Active

人物ノードに顔写真を添えられること。表示の有無を切り替えられること。実データには 75 枚の写真が含まれる。

### 人物枠

**UID**: RQ-03-08 \
**STATUS**: Active

人物を罫線で囲む表示と、囲まない表示を切り替えられること。サンプル画像には両方の様式が存在する。

### 故人の表現と凡例

**UID**: RQ-03-09 \
**STATUS**: Active

物故者を視覚的に区別して表示し、その意味を示す凡例を図中に配置できること。没年イベントの有無で判定する。

### 注記の小書き

**UID**: RQ-03-10 \
**STATUS**: Active

人物に紐づくメモを小書きとして添えられること。サンプル画像の「実父 山田太郎」のように、養子の出自などを補足する用途を想定する。

### 基準人物の強調

**UID**: RQ-03-11 \
**STATUS**: Active

利用者が指定した基準人物を、他と区別できる形で強調表示できること。

### 表示項目の一括切替

**UID**: RQ-03-12 \
**STATUS**: Active

ふりがな・続柄・生没年・顔写真・注記・旧姓の各項目について、図全体での表示/非表示を一括で切り替えられること。

## 4. 暦表示

### 西暦・和暦の切替

**UID**: RQ-04-01 \
**STATUS**: Active

日付表記を西暦と和暦で切り替えられること。

### 和暦の漢数字表記

**UID**: RQ-04-02 \
**STATUS**: Active

和暦表示では年月日を漢数字で表記すること（例:「明治二十七年八月十二日生」）。算用数字ではサンプル画像の様式にならない。

### 元号テーブルの範囲

**UID**: RQ-04-03 \
**STATUS**: Active

元号テーブルは天保以降（天保・弘化・嘉永・安政・万延・文久・元治・慶応・明治・大正・昭和・平成・令和）を網羅すること。実データの最古の日付は 1833 年である。

### 改元境界の扱い

**UID**: RQ-04-04 \
**STATUS**: Active

改元日をまたぐ日付を正しい元号に割り当てること。改元年は旧元号・新元号のいずれでも表記しうるため、日付単位で判定すること（例: 1912-07-30 は大正元年、1912-07-29 は明治 45 年）。

### 明治 6 年以前の日付の扱い

**UID**: RQ-04-05 \
**STATUS**: Active

日本が太陽暦を採用したのは明治 6 年 (1873) であり、それ以前の日付は旧暦（天保暦）である。Gramps の `dateval` に格納された値が旧暦の日付そのものか、グレゴリオ暦へ換算済みの値かは判別できない。誤った月日を断定的に表示しないこと。実データには 4 件（1833・1840・1863・1864 年）が該当する。

### 不明・概算日付の表記

**UID**: RQ-04-06 \
**STATUS**: Active

日付の一部または全部が不明な場合、判明している範囲のみを表示すること。「およそ」「以前」「以後」「推定」の修飾、および期間・範囲表現を表記に反映できること。

### 西暦と和暦の併置

**UID**: RQ-04-07 \
**STATUS**: Draft

西暦と和暦を併記できること。発展的機能とする。

## 5. 表示範囲とレイアウト編集

### 全人物の表示

**UID**: RQ-05-01 \
**STATUS**: Active

データに含まれる全人物を 1 つの図に表示できること。

### 枝の表示・非表示

**UID**: RQ-05-02 \
**STATUS**: Active

指定した人物を起点とする子孫または祖先の枝を、表示・非表示に切り替えられること。

### 起点人物の指定

**UID**: RQ-05-03 \
**STATUS**: Active

図の起点となる人物を指定し、そこから辿れる範囲のみを描画できること。

### 自動レイアウトの実行

**UID**: RQ-05-04 \
**STATUS**: Active

利用者の操作により自動レイアウトを実行し、人物の配置を機械的に決定できること。

### レイアウトの手動調整

**UID**: RQ-05-05 \
**STATUS**: Active

人物ノードの位置を手動で移動できること。

### 操作の取り消しとやり直し

**UID**: RQ-05-06 \
**STATUS**: Active

レイアウトに関するすべての操作を取り消し・やり直しできること。**自動レイアウトの実行そのものも取り消し可能**であり、実行前の配置に戻せること。

### 手動調整の保持

**UID**: RQ-05-07 \
**STATUS**: Active

手動調整の内容を自動レイアウト結果とは独立に保持し、自動レイアウトの再実行によって無条件に失われないこと。

### プロジェクトの保存と再開

**UID**: RQ-05-08 \
**STATUS**: Active

表示設定・手動調整・標題などの編集内容を保存し、後から再開できること。保存データは `.gpkg` 本体とは分離し、元データを書き換えないこと。

### 画面上の閲覧操作

**UID**: RQ-05-09 \
**STATUS**: Active

図の拡大・縮小および移動が行えること。

### ノード単位の表示・非表示

**UID**: RQ-05-10 \
**STATUS**: Active

RQ-05-02 の枝単位の表示・非表示に加え、個々の人物ノードを単体で非表示にできること。関係が薄い古い世代で兄弟が多い場合など、枝全体ではなく特定の人物だけを一時的に隠したいケースに対応する。非表示にした人物へつながる婚姻線・親子接続線も連動して非表示になること。非表示にした人物は、隣接する（親・子・配偶者・兄弟の）可視な人物から再表示できること。

### 複数ノードのまとめ選択・移動

**UID**: RQ-05-11 \
**STATUS**: Active

複数の人物ノードをまとめて選択し、選択したノードをまとめてドラッグ移動できること。RQ-05-05 (手動調整) を1件ずつ行う手間を軽減するための機能とする。選択操作は既存の画面移動（パン、RQ-05-09）と衝突しない操作系にすること。

## 6. 意匠

### 標題

**UID**: RQ-06-01 \
**STATUS**: Active

図に標題（例:「山田家系図」）を掲げられること。既定では毛筆体の縦書きで図の右端に配置し、文言・書体・大きさ・位置を調整できること。位置は右側・縦書き、または上部・横書きから選択できること。

### 書体の選択

**UID**: RQ-06-02 \
**STATUS**: Active

本文・標題それぞれについて書体（行書体・楷書体・明朝体など）を選択できること。ローカル環境で完結して動作するため (RQ-08-01)、必要な書体は同梱するかローカルフォントを指定する。

### 配色

**UID**: RQ-06-03 \
**STATUS**: Active

文字色・線色・背景色・強調色を設定できること。

## 7. 出力・印刷

### 印刷ビュー

**UID**: RQ-07-01 \
**STATUS**: Active

印刷結果に対応した表示を画面上で確認できること。

### 用紙サイズと向き

**UID**: RQ-07-02 \
**STATUS**: Active

用紙サイズ・向き・余白を指定し、図全体が収まるよう倍率を自動調整できること。

### 系統分割

**UID**: RQ-07-03 \
**STATUS**: Active

1 枚に収めるには大きすぎる家系図を、系統ごとに分割して複数枚に出力できること。サンプル画像の「1 系統 / 2 系統」に相当する。分割の単位は利用者が指定できること。

### A4 タイル印刷

**UID**: RQ-07-04 \
**STATUS**: Active

大判の図を A4 用紙に分割して印刷し、貼り合わせて 1 枚に復元できること。各ページには のりしろ・トンボ・ページ番号・貼り合わせ順を示す情報を付すこと。

### PDF 出力

**UID**: RQ-07-05 \
**STATUS**: Active

印刷対応の PDF を出力できること。

### SVG / PNG 出力

**UID**: RQ-07-06 \
**STATUS**: Active

SVG および PNG 形式で出力できること。

## 8. 非機能要求

### ローカル実行

**UID**: RQ-08-01 \
**STATUS**: Active

個人の家系情報という機微なデータを扱うため、利用者のローカル環境で完結して動作し、家系データを外部へ送信しないこと。

### 規模への対応

**UID**: RQ-08-02 \
**STATUS**: Active

実データ規模（人物 136 名・8 世代）において、閲覧・編集操作が実用的な応答速度で行えること。将来的な規模の増加を想定し、アルゴリズムの計算量に注意すること。

### コアロジックの検証可能性

**UID**: RQ-08-03 \
**STATUS**: Active

データ解釈・暦変換・レイアウト計算といった中核ロジックを、画面描画に依存せず自動テストで検証できること。

### 文字の再現性

**UID**: RQ-08-04 \
**STATUS**: Active

家系図には旧字体・異体字（渡邊／渡邉、髙 など）が現れる。入力データの文字をそのまま保持し、正規化や文字化けによって別字に置き換えないこと。
